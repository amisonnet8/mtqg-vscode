.bcuz/	Record of the commands run through bcuz (committed)

.claude/	Claude Code settings shared in the repository
	hooks/	Hooks that Claude Code runs around its tools
		build.sh	After srwr edit or new changes a .ts, package.json or tsconfig.json, runs qsoku build and reports a failure
		crube-untracked.sh	After srwr new creates a file, tells Claude which of its paths have no description, per language
		require-bcuz.sh	PreToolUse hook that refuses Bash commands not run through bcuz
		require-bcuz.test.sh	Table of the commands require-bcuz.sh allows and refuses (qsoku hook)
	rules/	Rules for working in this repository (Japanese); CLAUDE.md says when to read each
		bcuz-usage.md	How to run Bash commands through bcuz, and keeping secrets out of them
		crube-usage.md	Using crube: MCP and the CLI, finding places, keeping descriptions in both languages
		datetime.md	Dates and times: keep UTC, show in the local time zone
		dependencies.md	npm dependencies: none at run time; only Microsoft's and TypeScript for development
		directory-structure.md	Where each file goes, and the layout of the repository
		distribution.md	Releases: a pushed tag makes the GitHub Release with the .vsix; people publish to the Marketplace
		documentation.md	How to write documents: example values from tools, what history goes in docs/design/
		mtqg-cli.md	How the extension calls the mtqg CLI: execFile, --json, errors, MTQG_TTY, versions
		mtqg-usage.md	How to record memos, todos, questions, bugs and rules with mtqg
		naming.md	Names: mtqg's terms as they are, in the code and the UI
		qsoku-usage.md	The qsoku names for build, test and lint, and how to call them
		srwr-usage.md	Editing files only through srwr (strict mode), and closing tapes
		testing.md	Test policy, and pitfalls of the sandbox and of CI on each OS
		ui.md	UI policy: English, not relying on text, six screens, no new features
		working-with-human.md	How to ask people: small blockers, checks, and approval of what users see
	settings.json	Permissions, sandbox and hooks of Claude Code (managed by people)

.srwr/	srwr: tapes of the file edits made by AI, each with its reason

		| One compressed tape (*.tape.jsonl.gz) for each unit of work.
		| The tapes are left out by .crube/ignore, so that they need no description.

src/	Source of the extension (TypeScript)
	extension.ts	Entry point: registers the mtqg.open command and the panel serializer
	mtqg/	Calls the mtqg CLI as a child process and types its --json output
		availability.ts	Checks that mtqg is on PATH and new enough (MIN_SUPPORTED_MTQG_VERSION)
		client.ts	One typed function for each mtqg command the extension uses
		errors.ts	Errors and warnings parsed from mtqg's --json lines on standard error
		index.ts	What src/mtqg/ exports
		process.ts	Runs mtqg with execFile and --json, and parses its output
		types.ts	Types of the --json output of mtqg that the extension reads
	webview/	The mtqg panel: a Webview with six tabs
		client/	Script that runs inside the Webview (DOM types, browser ES modules, its own tsconfig)
			main.ts	Puts the HTML from the host in place and sends clicks and input back to the host
			tsconfig.json	Compiler settings for the Webview script
		controller.ts	Webview message to mtqg call to render; keeps the view state (no vscode)
		panel.ts	Opens, reveals and restores the WebviewPanel; the only file here that touches vscode
		screens.ts	renderScreen sends each tab to its renderer; renderError
		screens/	HTML of each screen, built on the host (no vscode)
			bugs.ts	Bug screen: renderThread with the bug and reply labels
			composer.ts	Parses the slash commands of the Memo input (/todo, /t and the others)
			format.ts	Formats dates for display in the user's time zone
			glossary.ts	Glossary screen: a table, with words defined more than once marked
			memos.ts	Memo screen: the timeline of every kind of record, from log --events
			questions.ts	QA screen: renderThread with the question and answer labels
			rules.ts	Rule screen: a plain table
			table.ts	Parts the screens share: editable text, delete and ID buttons, badges
			thread.ts	Thread screen shared by QA and Bug: rows with their replies, and a reply box
			todos.ts	Todo screen: Keep-like cards, done ones above the open ones
		shared/	Shared by the six screens (no vscode)
			escape.ts	Escapes text before it goes into HTML
			html.ts	renderShell: CSP, tab bar and the tab panels around the screens
			messages.ts	Types and validation of the messages between the host and the Webview
			tabs.ts	IDs, labels and the default of the six tabs
