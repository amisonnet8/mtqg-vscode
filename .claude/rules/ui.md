# UIの方針

出典：mtqg設計`docs/design/07-integrations.md` §11.4（このリポジトリの`docs/design/01-vscode-extension.md`に写しがある）。

## UIを豊かにする理由

- 人間との作業で威力が出る画面。人間には記録を強制できないので、使いたくなる体験を作る
- 人間同士の質問や相談は、今はSlackやDiscordで行われ流れて消えていく。見慣れたチャットの形にすることで、人がすでに持っている習慣をそのままリポジトリの中に持ち込む

## UIの言語：英語、文字に頼らない

- UIの文言（ボタン、見出し、メニュー、通知）は**英語**。入力と記録の中身は書かれた言語のまま（翻訳しない）
- **文字にあまり頼らないUIにする。** チェックボックス、アイコン、色、スレッドの形など、見れば分かる要素で状態を伝える。**色だけで意味を伝えない**
- 多言語化の仕組みは持たない

## 原則：UIは豊かにするが、機能は足さない

- UIは、**過程を残すアシスト**として豊かにする。新しいデータや操作を増やさず、すでにある記録を「書きやすく、見やすく」する
- 参考にするUIの機能（Keepのリマインダー・色分け・ピン留め、Slackの通知・リアクション等）は真似ない。判断の問いは「それは課題を管理するための機能か、過程を残すための情報か」（mtqg設計§2.7）

## 画面構成

**当初の設計（§11.4初版、2026-09-20）は4画面（ToDo・QA・用語集・メモ）で、bug（09-21追加）・rule（09-25追加）が抜けていた。mtqg本体側の見直し（2026-09-26、§11.4「見直し：bugとruleの画面」）でBugs・Rulesの2画面を足し、6画面になった。**

| 画面 | 形 | 表示範囲 |
|---|---|---|
| ToDo | Google Keep風のカード | 全件（デフォルトは未完了のみ） |
| QA | 表 | 全件（デフォルトは未回答のみ） |
| Bugs | 表（QAと同じ形） | 全件（デフォルトは未クローズのみ） |
| Rules | ただの表 | 全件 |
| 用語集 | ただの表 | 全件 |
| メモ | Slack・Discord風のタイムライン（他の種類も含む） | 最近の分から表示し、遡るときに読み込む |

- 6つの画面はタブで切り替える。どれも、mtqgの`--json`が返す**同じデータの見え方**にすぎない。**実際のタブバーの並び・ラベルは、人間の指示（2026-09-26、q&a`70787501f3f3`）で`Memo・Todo・QA・Bugs・Rules・Glossary`（Memoが先頭、単数形、QAは省略形）にしている**（この表の並びは元の設計の写しとして残す。`src/webview/shared/tabs.ts`が実装）
- ToDo・QA・Bugs・Rules・用語集は「管理する対象」で件数に自然な上限があるので全件表示、メモは「流れていく記録」で件数に上限がないので最近の分から遡る

### ToDo：Keep風のカード

チェックボックス付きのカード。チェックすれば完了（内部では`todo done`）。デフォルトは未完了のみ、切り替えで完了済みも表示

### QA：表

デフォルトは未回答のみ。「答えるべきものが残っている」ことが一目で分かることが最優先。質問を開くと回答が見える

### Bugs：表（QAと同じ形）

QAと同じ形の別画面にする（統合しない。モデル層の実装はqaと共通だが、質問と不具合は読み手にとって意味が違うカテゴリなので画面を分ける）。デフォルトは未クローズ（open）のみ、切り替えでクローズ済みも表示。バグを開くと返信（やり取り）が見える

### Rules：ただの表

用語集と同じ「ただの表」の形にする。ruleは`word`を持たないので列は本文・記録者・日付だけ。用語集と同じく**全件表示、archiveされない**。メモのタイムラインに埋もれさせず、常に一覧できる場所にする

### 用語集：ただの表

用語、定義、記録者、日付の列。同じ用語が別々に定義されている場合だけ並べて目立たせる

### メモ：Slack・Discord風のタイムライン

チャットの見慣れた作法とmtqgの仕組みの対応：

| チャットの作法 | mtqgの仕組み |
|---|---|
| 新しい発言は下に追加、過去の発言は動かない | 追記するだけ |
| 発言を直すと「（編集済み）」と表示 | 訂正の事実を追記し、直したことを見せる |
| 消すと跡が残る | 削除の事実を追記し、消えないことを正直に見せる |
| 質問への返信がスレッドにぶら下がる | qaの回答は親への参照を持つ記録 |
| 発言者のアイコンと名前 | 記録者。人間とAIの記録が同じタイムラインに並ぶ |

todoはチェックボックス付きの投稿として流れ完了は控えめな行で表示、qaはスレッドになり回答は返信としてぶら下がる、bugも同じくスレッドになり返信がぶら下がる、glossaryは「Defined a term」という投稿として流れる、ruleは「Adopted a rule」という投稿として流れる。入力欄は普段はmemoとして投稿し、`/todo`・`/qa`・`/bug`・`/glossary`・`/rule`のようなスラッシュコマンドで種類を書き分ける。**それぞれ`/t`・`/q`・`/b`・`/g`・`/r`の1文字の短縮形も使える**（人間の指示、2026-09-26、q&a`70787501f3f3`、`src/webview/screens/composer.ts`）。

**「消すと跡が残る」は、今のCLIでは実現できない。** `mtqg log`は`--events`を付けても削除された記録を一切返さない（実機で確認、todo`01ee2706ce`）。Memo画面は他の5画面と同じく、削除されたら見えなくなる形にしている。跡を残す機能が要るなら、mtqg本体への機能要望として改めて扱う（`docs/design/01-vscode-extension.md`「Memo画面の実装」）。

## レイアウトの詳細は未定

各画面の具体的なレイアウト（列の並び、余白、詳細表示の形など）はmtqg設計「14章」に送られていて、まだ決まっていない。実装するときに人間へ確認する（推測で決めない）。
